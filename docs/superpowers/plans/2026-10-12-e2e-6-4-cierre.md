# E2E 6.4: latencia, run-all y cierre de la fase 6 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Completar la fase 6: el escenario 11 (medición de latencia con informe `docs/results/latency.md`) y `e2e/run-all.sh`, que ejecuta los 11 escenarios, resume PASS/FAIL, recoge las métricas y puede reiniciar el stack y escribir un informe.

**Architecture:** Las funciones de informe y de ejecución de escenarios son puras o casi (`e2e/report.sh`) y se prueban sin Docker con escenarios simulados. `11-latency.sh` mide N ventas secuenciales leyendo el `lastEventLatencyMs` del Catálogo; `run-all.sh` ejecuta cada escenario como subproceso aislado, en secuencia, continúa tras los fallos y solo recoge las líneas `METRIC` de los escenarios que terminan bien.

**Tech Stack:** bash, curl, jq, awk, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-12-e2e-design.md` (§3 escenario 11, §4 orquestación, §5 sub-tarea 6.4, §2 `lib.sh`). Medición y comparación con el "antes": `docs/superpowers/specs/2026-10-09-solucion-global-design.md` §6.

## Global Constraints

- Nombres de archivos, funciones y variables en **inglés y completos**; mensajes de salida, comentarios y documentación en **español**. Commits en inglés, Conventional Commits, con la línea `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- `set -uo pipefail` **sin `-e`**; todos los `.sh` ejecutables. Requieren bash 5 y GNU `date`.
- Se ejecutan contra el stack de desarrollo (proyecto Compose `retail`) con los puertos por defecto.
- Escenario 11: SKU `GORRA-SPORT-NEGRA` (stock sembrado 50, caben 2 ejecuciones de 20 por reinicio); `LATENCY_SALES` (20), `LATENCY_P95_LIMIT_MS` (1000), `LATENCY_REPORT` (por defecto `docs/results/latency.md`); ventas **una tras otra** alternando POS y ONLINE; la latencia es el `lastEventLatencyMs` del Catálogo (`updatedAt − occurredAt`); **falla si el p95 supera el límite**; el informe solo se escribe si se midieron las N ventas; métricas `latency_min_ms`, `latency_average_ms`, `latency_p95_ms`, `latency_max_ms`.
- "Antes" (spec global §6): peor caso 30 min (1 800 000 ms), promedio ~15 min (900 000 ms), ventana de sobreventa hasta 30 min.
- `run-all.sh [--reset] [--report <archivo>]`: **no** reinicia el stack salvo con `--reset` (destructivo); no admite `--demo`; argumento desconocido o `--report` sin archivo → uso y código 2; cada escenario como subproceso (`bash script`, nunca `source`), en secuencia (el 08 corta todos los consumidores), continúa tras un fallo; exige exactamente 11 escenarios (`NN-*.sh`); código de salida distinto de cero si alguno falló; solo recoge las líneas `METRIC` de escenarios que terminan bien.
- Un `run-all.sh` completo consume stock (TENIS 3, MOCHILA 3, BOTELLA 2, GORRA 20; BALON y el 03 solo corren una vez): una segunda ejecución sin reinicio falla en 01/02/03/07 con "Estado no inicial"; para repetir hay que usar `--reset`.
- La ruta del repositorio contiene espacios: toda ruta en el código va entre comillas dobles.

## Review Focus

1. **Un escenario que falla no debe detener ni contaminar la ejecución:** `run-all.sh` continúa, marca FAIL, devuelve distinto de cero y **no** recoge las métricas de ese escenario (incluidas las `latency_*` si el p95 supera el límite). Lo fijan la autoprueba (escenarios simulados) y las mutaciones de la Tarea 2.
2. **Evidencia de latencia incompleta o falsa:** el informe solo se escribe si se midieron todas las ventas; el veredicto "cumple" sale de la comparación real del p95 con el límite; promedio y p95 salen de las mismas muestras. Lo fija la autoprueba (`render_latency_report`) y la mutación del límite.
3. **Un escenario que desaparece o se renombra:** `run-all.sh` exige exactamente 11 `NN-*.sh` y falla antes de ejecutar nada si no los hay.
4. **Reinicio silencioso:** `run-all.sh` nunca ejecuta `reset.sh` sin `--reset`; con el stack apagado y sin `--reset` falla con el mensaje de levantar el stack (código 1).
5. **Entradas inválidas:** `LATENCY_SALES` y `LATENCY_P95_LIMIT_MS` no numéricos o cero fallan antes de tocar el stack; argumentos desconocidos o `--demo` en `run-all.sh` dan uso y código 2.
6. **Aislamiento entre escenarios:** los traps de los escenarios que detienen contenedores (05, 08) no se mezclan con los de `run-all.sh` porque cada uno es un subproceso.

`e2e/report.sh`:

```bash
#!/usr/bin/env bash
# Informes y ejecución de escenarios (spec E2E §3 y §4). Se carga con `source` después de lib.sh; no ejecuta nada
# por sí sola. Las usan 11-latency.sh y run-all.sh, y las prueba selftest.sh sin Docker.

# "Antes" del proceso por lotes del retail (spec global §6): cada 30 min, así que el peor caso es 30 min y el
# promedio ~15 min.
BEFORE_WORST_CASE_MS=1800000
BEFORE_AVERAGE_MS=900000

# Resultados de run_scenario, en el orden de ejecución.
RESULT_NAMES=()
RESULT_STATUS=()
RESULT_DURATION_MS=()
METRIC_LINES=()

# format_duration_ms <ms>: duración en segundos con un decimal (por ejemplo "6.5 s").
format_duration_ms() { awk -v ms="$1" 'BEGIN { printf "%.1f s", ms / 1000 }'; }

# improvement_factor <antes_ms> <después_ms>: cuántas veces menor es el segundo valor (entero hacia abajo; un
# "después" menor que 1 ms se toma como 1 ms).
improvement_factor() {
  awk -v before="$1" -v after="$2" 'BEGIN { if (after < 1) after = 1; printf "%d", before / after }'
}

# render_latency_report <fecha UTC> <sku> <límite p95 ms> <mínimo> <promedio> <p95> <máximo> <CANAL:ms...>
# Imprime el informe de latencia en Markdown (docs/results/latency.md).
render_latency_report() {
  local timestamp="$1" sku="$2" limit="$3" minimum="$4" average="$5" p95="$6" maximum="$7"
  shift 7
  local verdict="sí" sample index=0
  awk -v p95="$p95" -v limit="$limit" 'BEGIN { exit !(p95 > limit) }' && verdict="no"
  printf '# Latencia de propagación venta → Catálogo\n\n'
  printf -- '- **Fecha (UTC):** %s\n' "$timestamp"
  printf -- '- **Muestras:** %s ventas de `%s`, alternando POS y online, una tras otra\n' "$#" "$sku"
  printf -- '- **Definición:** `lastEventLatencyMs` del Catálogo = `updatedAt − occurredAt` (momento en que el\n'
  printf '  Catálogo aplica el evento menos el momento de la venta); los contenedores comparten el reloj del anfitrión\n'
  printf -- '- **Objetivo:** p95 por debajo de %s ms; **cumple: %s**\n\n' "$limit" "$verdict"
  printf '| Mínimo | Promedio | p95 | Máximo |\n|---|---|---|---|\n'
  printf '| %s ms | %s ms | %s ms | %s ms |\n\n' "$minimum" "$average" "$p95" "$maximum"
  printf '## Comparación con el proceso por lotes ("antes")\n\n'
  printf '| | Antes (lotes cada 30 min) | Después (eventos) |\n|---|---|---|\n'
  printf '| Peor caso | 30 min (%s ms) | p95 medido: %s ms |\n' "$BEFORE_WORST_CASE_MS" "$p95"
  printf '| Promedio | ~15 min (%s ms) | promedio medido: %s ms |\n' "$BEFORE_AVERAGE_MS" "$average"
  printf '| Ventana de sobreventa | Hasta 30 min | Hasta la latencia medida; Inventario rechaza toda venta sin stock |\n\n'
  printf 'El peor caso medido (p95) es unas **%s veces** menor que el peor caso del proceso por lotes.\n\n' \
    "$(improvement_factor "$BEFORE_WORST_CASE_MS" "$p95")"
  printf '## Muestras\n\n| # | Canal | Latencia (ms) |\n|---|---|---|\n'
  for sample in "$@"; do
    index=$((index + 1))
    printf '| %s | %s | %s |\n' "$index" "${sample%%:*}" "${sample#*:}"
  done
}

# run_scenario <script>: ejecuta un escenario como subproceso (nunca con source: sus traps no deben mezclarse), muestra
# su salida en vivo y registra nombre, resultado, duración y, solo si terminó bien, sus líneas METRIC.
run_scenario() {
  local script="$1" name log start status line
  name="$(basename "$script" .sh)"
  log="$(mktemp)"
  printf '\n=== %s ===\n' "$name"
  start="$(now_ms)"
  bash "$script" 2>&1 | tee "$log"
  status="${PIPESTATUS[0]}"
  RESULT_NAMES+=("$name")
  RESULT_DURATION_MS+=("$(( $(now_ms) - start ))")
  if [[ "$status" == "0" ]]; then
    RESULT_STATUS+=("PASS")
    while IFS= read -r line; do
      METRIC_LINES+=("${line#METRIC }")
    done < <(grep '^METRIC ' "$log")
  else
    RESULT_STATUS+=("FAIL")
  fi
  rm -f "$log"
}

# count_passed: cuántos escenarios registrados terminaron bien.
count_passed() {
  local count=0 status
  for status in "${RESULT_STATUS[@]}"; do
    [[ "$status" == "PASS" ]] && count=$((count + 1))
  done
  echo "$count"
}

# render_summary: resumen en texto de los escenarios ejecutados y sus métricas.
render_summary() {
  local index
  printf '\n== Resumen ==\n'
  printf '%-28s %-9s %s\n' "Escenario" "Resultado" "Duración"
  for index in "${!RESULT_NAMES[@]}"; do
    printf '%-28s %-9s %s\n' "${RESULT_NAMES[index]}" "${RESULT_STATUS[index]}" \
      "$(format_duration_ms "${RESULT_DURATION_MS[index]}")"
  done
  if (( ${#METRIC_LINES[@]} > 0 )); then
    printf '\nMétricas:\n'
    printf '  %s\n' "${METRIC_LINES[@]}"
  fi
  printf '\n%s de %s escenarios OK\n' "$(count_passed)" "${#RESULT_NAMES[@]}"
}

# render_run_report <fecha UTC>: lo mismo que render_summary, en Markdown (opción --report de run-all.sh).
render_run_report() {
  local index metric
  printf '# Resultados de la ejecución E2E\n\n'
  printf -- '- **Fecha (UTC):** %s\n' "$1"
  printf -- '- **Resultado:** %s de %s escenarios OK\n\n' "$(count_passed)" "${#RESULT_NAMES[@]}"
  printf '| Escenario | Resultado | Duración |\n|---|---|---|\n'
  for index in "${!RESULT_NAMES[@]}"; do
    printf '| %s | %s | %s |\n' "${RESULT_NAMES[index]}" "${RESULT_STATUS[index]}" \
      "$(format_duration_ms "${RESULT_DURATION_MS[index]}")"
  done
  if (( ${#METRIC_LINES[@]} > 0 )); then
    printf '\n## Métricas\n\n| Métrica | Valor |\n|---|---|\n'
    for metric in "${METRIC_LINES[@]}"; do
      printf '| %s | %s |\n' "${metric%%=*}" "${metric#*=}"
    done
  fi
}
```

#!/usr/bin/env bash
# Escenario 11 — Latencia (spec global §4.2 y §6): mide cuánto tarda una venta en reflejarse en el Catálogo.
# Registra LATENCY_SALES ventas (20 por defecto) de GORRA-SPORT-NEGRA alternando POS y online, una tras otra; lee el
# lastEventLatencyMs de cada una, calcula mínimo, promedio, p95 y máximo, y escribe el informe (por defecto
# docs/results/latency.md, o LATENCY_REPORT). Falla si el p95 supera LATENCY_P95_LIMIT_MS (1000 ms por defecto).
# Consume LATENCY_SALES unidades de stock (sembrado 50: caben 2 ejecuciones de 20 por reinicio).
# Uso: e2e/11-latency.sh [--demo]
set -uo pipefail
source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"
source "$(dirname "${BASH_SOURCE[0]}")/report.sh"
e2e_init "$@"
SKU="GORRA-SPORT-NEGRA"
SALES="${LATENCY_SALES:-20}"
P95_LIMIT_MS="${LATENCY_P95_LIMIT_MS:-1000}"
REPORT_FILE="${LATENCY_REPORT:-$E2E_ROOT/docs/results/latency.md}"

[[ "$SALES" =~ ^[1-9][0-9]*$ ]] || fail_precondition "LATENCY_SALES debe ser un entero positivo (valor: $SALES)"
[[ "$P95_LIMIT_MS" =~ ^[1-9][0-9]*$ ]] || fail_precondition "LATENCY_P95_LIMIT_MS debe ser un entero positivo (valor: $P95_LIMIT_MS)"

require_stack
require_synced "$SKU"
require_stock "$SKU" "$SALES"
stock_before="$(catalog_stock "$SKU")"

step "Registra $SALES ventas de $SKU, una tras otra, alternando POS y online"
latencies=()
samples=()
for index in $(seq 1 "$SALES"); do
  channel="POS"
  (( index % 2 == 0 )) && channel="ONLINE"
  sell "$SKU" "$channel"
  if [[ "$SELL_STATUS" != "201" ]]; then
    check "la venta $index ($channel) responde 201" "$SELL_STATUS" "201"
    break
  fi
  wait_until "venta $index ($channel): el Catálogo muestra stock $((stock_before - index))" \
    catalog_stock_is "$SKU" "$((stock_before - index))" || break
  latency="$(catalog_field "$SKU" '.lastEventLatencyMs')"
  if [[ "$(is_integer "$latency")" != "yes" ]]; then
    check "lastEventLatencyMs de la venta $index se informa" "$latency" "un entero"
    break
  fi
  echo "INFO: venta $index ($channel): latencia ${latency} ms"
  latencies+=("$latency")
  samples+=("$channel:$latency")
done
check "se midieron las $SALES ventas" "${#latencies[@]}" "$SALES"

if (( ${#latencies[@]} == SALES )); then
  statistics "${latencies[@]}"
  step "Resultado: mínimo ${STAT_MIN} ms, promedio ${STAT_AVERAGE} ms, p95 ${STAT_P95} ms, máximo ${STAT_MAX} ms"
  check "el p95 (${STAT_P95} ms) no supera ${P95_LIMIT_MS} ms" \
    "$([[ "$STAT_P95" -le "$P95_LIMIT_MS" ]] && echo yes || echo no)" "yes"
  metric latency_min_ms "$STAT_MIN"
  metric latency_average_ms "$STAT_AVERAGE"
  metric latency_p95_ms "$STAT_P95"
  metric latency_max_ms "$STAT_MAX"
  mkdir -p "$(dirname "$REPORT_FILE")"
  render_latency_report "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$SKU" "$P95_LIMIT_MS" \
    "$STAT_MIN" "$STAT_AVERAGE" "$STAT_P95" "$STAT_MAX" "${samples[@]}" >"$REPORT_FILE"
  echo "INFO: informe de latencia escrito en $REPORT_FILE"
fi

finish "11 Latencia"
