# E2E 6.3: Catálogo caído y RabbitMQ caído — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agregar los escenarios 05 (Catálogo caído) y 08 (RabbitMQ caído), que detienen y reinician contenedores del Compose, con los ayudantes de `lib.sh` para detener, restaurar y medir, y la garantía de que el sistema vuelve a su estado normal aunque el escenario falle o se interrumpa.

**Architecture:** `stop_service` detiene un contenedor y lo registra; `start_service` lo levanta y espera a que esté sano; un `trap` de salida (`install_restore_trap`, también ante Ctrl+C y señal de terminación) levanta lo que quede detenido. Los escenarios comprueban el efecto con el outbox de Inventario (estado `PENDING`/`PUBLISHED` por `eventId`), los conteos y consumidores de la cola (`rabbitmqctl`) y el orden de aplicación leído del log del Catálogo, y emiten métricas con el formato fijo `METRIC nombre=valor` para que `run-all.sh` (6.4) las recoja.

**Tech Stack:** bash, curl, jq, Docker Compose (`stop`, `up -d --wait --no-recreate`), `rabbitmqctl`.

**Spec:** `docs/superpowers/specs/2026-10-12-e2e-design.md` (§2 `lib.sh`, §3 escenarios 05 y 08, §6 Pendientes). Escenarios: `docs/superpowers/specs/2026-10-09-solucion-global-design.md` §4.2.

## Global Constraints

- Nombres de archivos, funciones y variables en **inglés y completos**; mensajes de salida, comentarios y documentación en **español**. Commits en inglés, Conventional Commits, con la línea `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- `set -uo pipefail` **sin `-e`**; todos los `.sh` ejecutables. Requieren bash 5 y GNU `date`.
- Se ejecutan contra el stack de desarrollo (proyecto Compose `retail`) con los puertos por defecto. Servicios del Compose: `catalog-service`, `inventory-service`, `rabbitmq`, `catalog-db`, `inventory-db`.
- SKU: 05 `MOCHILA-TRAIL-20L` (3 ventas; stock sembrado 10, así que caben 3 ejecuciones por reinicio); 08 `BOTELLA-TERMICA-750` (2 ventas; stock 10, caben 5 ejecuciones).
- Un escenario que detiene un contenedor **siempre** lo restaura al terminar: por éxito, por fallo (`finish`) o por interrupción (SIGINT → código 130, SIGTERM → código 143).
- Las condiciones de `wait_until` son funciones que se reevalúan (nunca `test "$(comando)" = x`, que se evalúa una sola vez). Las lecturas que alimentan una comparación deben ser enteros válidos o la comparación debe fallar (lección de la 6.1).
- Las métricas se imprimen con `metric <nombre> <valor>` → `METRIC <nombre>=<valor>`; nombres fijos: `catalog_catch_up_ms` (05), `outbox_drain_ms` y `broker_recovery_catch_up_ms` (08). Se miden desde que se reinicia el servicio.
- Tiempo máximo de espera tras reiniciar el broker o el Catálogo: 90 s por llamada (`WAIT_TIMEOUT_SECONDS=90 wait_until …`); medido: el broker vuelve sano en ~6 s y el outbox y el Catálogo convergen entre ~6 y ~11 s después (hasta ~25 s observados en otra ocasión).
- La ruta del repositorio contiene espacios: toda ruta en el código va entre comillas dobles.

## Review Focus

1. **Servicio que queda detenido** si el escenario falla o se interrumpe: el `trap` debe levantarlo (comprobado con señales reales SIGINT/SIGTERM y con mutaciones que no reinician el servicio).
2. **Esperas que no reintentan** o comparaciones que pasan en falso con lecturas vacías: `outbox_count_with_status`, `catalog_applied_sequence` y `queue_consumers` devuelven vacío/1 ante respuestas inválidas y la autoprueba lo fija.
3. **"En orden" y "cero eventos perdidos"**: el log del Catálogo trae cada `eventId` dos veces por línea (cabecera MDC y mensaje); un extractor ingenuo duplica los ids y falla el orden. La autoprueba lo cubre con una línea de log realista.
4. **Estado inicial**: el stock de MOCHILA/BOTELLA se agota tras 3 / 5 ejecuciones; el escenario debe fallar con "Estado no inicial: ejecuta e2e/reset.sh", no con un error críptico.
5. **Eventos de la ventana de caída**: con el Catálogo caído la cola acumula exactamente las ventas (con 0 consumidores); con RabbitMQ caído el outbox las conserva `PENDING` y el Catálogo sigue sano y sin cambios.
6. **Tiempos de recuperación variables**: las esperas de recuperación usan 90 s y el escenario mide, no fija, la duración.

```bash
# --- Caídas de servicios (escenarios 05 y 08) y métricas ---

# Servicios detenidos por el escenario y aún no restaurados (ver stop_service y restore_services).
STOPPED_SERVICES=()

# now_ms: milisegundos desde la época (para medir tiempos).
now_ms() { date +%s%3N; }

# metric <nombre> <valor>: imprime una métrica con un formato fijo que run-all.sh puede recoger.
metric() { echo "METRIC $1=$2"; }

# stop_service <servicio>: detiene un contenedor del Compose y lo registra para restaurarlo al salir.
stop_service() {
  compose stop "$1" >/dev/null 2>&1 || return 1
  STOPPED_SERVICES+=("$1")
}

# start_service <servicio>: levanta el contenedor, espera a que esté sano y lo quita del registro.
start_service() {
  compose up -d --wait --wait-timeout 120 --no-recreate "$1" >/dev/null 2>&1 || return 1
  local remaining=() service
  for service in "${STOPPED_SERVICES[@]}"; do
    [[ "$service" != "$1" ]] && remaining+=("$service")
  done
  STOPPED_SERVICES=("${remaining[@]}")
}

# restore_services: levanta todo lo que el escenario dejó detenido. Se usa como trap de salida.
restore_services() {
  local pending=("${STOPPED_SERVICES[@]}") service
  for service in "${pending[@]}"; do
    echo "Restaurando $service..." >&2
    start_service "$service" || echo "FAIL: no se pudo restaurar $service; ejecuta e2e/reset.sh" >&2
  done
}

# install_restore_trap: garantiza que los servicios detenidos se levanten aunque el escenario falle o se
# interrumpa (Ctrl+C o señal de terminación).
install_restore_trap() {
  trap restore_services EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
}

# queue_consumers <cola>: consumidores conectados a una cola (rabbitmqctl).
queue_consumers() {
  compose exec -T rabbitmq rabbitmqctl -q list_queues name consumers | awk -v q="$1" '$1 == q {print $2}' | tr -d '\r'
}
# queue_consumers_is <cola> <cantidad> (para wait_until)
queue_consumers_is() { [[ "$(queue_consumers "$1")" == "$2" ]]; }

# outbox_count_with_status <estado> <eventId...>: cuántos de esos eventos tienen ese estado en el outbox.
outbox_count_with_status() {
  local status="$1"
  shift
  curl -s --max-time 10 "$INVENTORY_URL/api/v1/inventory/outbox?status=$status" \
    | jq --argjson ids "$(printf '%s\n' "$@" | jq -R . | jq -sc .)" \
      '[.[] | select(.eventId as $id | $ids | index($id))] | length' 2>/dev/null
}
# outbox_count_with_status_is <estado> <cantidad> <eventId...> (para wait_until)
outbox_count_with_status_is() { [[ "$(outbox_count_with_status "$1" "${@:3}")" == "$2" ]]; }

# catalog_applied_sequence <sku> <eventId...>: de esos eventId, los que el Catálogo aplicó (líneas event_applied del
# SKU), en el orden del log, uno por línea. Devuelve 1 si no puede leer el log.
catalog_applied_sequence() {
  local logs sku="$1"
  shift
  logs="$(compose logs --no-color catalog-service 2>/dev/null)" || return 1
  grep -o -- "event_applied sku=$sku eventId=[0-9a-f-]*" <<<"$logs" | sed 's/.*eventId=//' \
    | grep -Fx -f <(printf '%s\n' "$@") || true
}
```

`e2e/05-catalog-down.sh`:

```bash
#!/usr/bin/env bash
# Escenario 5 — Catálogo caído (spec global §4.2): con el Catálogo detenido los eventos se acumulan en la cola
# durable; al reiniciarlo se procesan todos, en orden, y el stock converge. Detiene un contenedor: el trap de
# salida lo vuelve a levantar aunque el escenario falle o se interrumpa.
# Mide la puesta al día del Catálogo (desde que se reinicia hasta que converge).
# Uso: e2e/05-catalog-down.sh [--demo]
set -uo pipefail
source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"
e2e_init "$@"
SKU="MOCHILA-TRAIL-20L"
SALES=3

require_stack
require_synced "$SKU"
require_stock "$SKU" "$SALES"
install_restore_trap
before="$(catalog_stock "$SKU")"

step "Detiene el Catálogo"
stop_service catalog-service
check "el Catálogo se detuvo" "$?" "0"
wait_until "la cola $QUEUE se queda sin consumidores" queue_consumers_is "$QUEUE" "0"

step "Registra $SALES ventas de $SKU mientras el Catálogo está caído"
sale_ids=()
for index in $(seq 1 "$SALES"); do
  channel="POS"
  (( index % 2 == 0 )) && channel="ONLINE"
  sell "$SKU" "$channel"
  check "la venta $index ($channel) responde 201" "$SELL_STATUS" "201"
  sale_ids+=("$(jq -r '.saleId' <<<"$SELL_BODY")")
done
wait_until "la cola acumula los $SALES mensajes" queue_messages_is "$QUEUE" "$SALES"

step "Reinicia el Catálogo"
restart_ms="$(now_ms)"
start_service catalog-service
check "el Catálogo vuelve a estar sano" "$?" "0"
wait_until "el Catálogo converge a stock $((before - SALES))" catalog_stock_is "$SKU" "$((before - SALES))"
catch_up_ms=$(( $(now_ms) - restart_ms ))
metric catalog_catch_up_ms "$catch_up_ms"
echo "INFO: puesta al día del Catálogo: ${catch_up_ms} ms (incluye el arranque del servicio)"

step "Comprobando que no se perdió ni se reordenó nada"
check "los eventos se aplicaron en el orden de las ventas" \
  "$(catalog_applied_sequence "$SKU" "${sale_ids[@]}" | paste -sd' ')" "${sale_ids[*]}"
wait_until "la cola $QUEUE queda vacía" queue_is_empty "$QUEUE"
wait_until "el Catálogo coincide con Inventario" synced "$SKU"

finish "05 Catálogo caído"
```

#!/usr/bin/env bash
# Escenario 8 — RabbitMQ caído (spec global §4.2): la venta se confirma y el evento queda PENDING en el outbox; al
# volver RabbitMQ el publicador lo envía y el Catálogo converge, sin perder ningún evento. Detiene un contenedor:
# el trap de salida lo vuelve a levantar aunque el escenario falle o se interrumpa.
# Mide el tiempo hasta vaciar el outbox y hasta que el Catálogo converge, desde que se reinicia RabbitMQ.
# Uso: e2e/08-broker-down.sh [--demo]

source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"
e2e_init "$@"
SKU="BOTELLA-TERMICA-750"
SALES=2
# La reconexión de los servicios tras volver el broker puede tardar (se observaron ~10 s y hasta ~25 s).
RECOVERY_TIMEOUT_SECONDS=90

require_stack
require_synced "$SKU"
require_stock "$SKU" "$SALES"
install_restore_trap
before="$(catalog_stock "$SKU")"

step "Detiene RabbitMQ"
stop_service rabbitmq
check "RabbitMQ se detuvo" "$?" "0"

step "Registra $SALES ventas de $SKU con RabbitMQ caído"
sale_ids=()
for index in $(seq 1 "$SALES"); do
  channel="POS"
  (( index % 2 == 0 )) && channel="ONLINE"
  sell "$SKU" "$channel"
  check "la venta $index ($channel) responde 201: Inventario sigue vendiendo" "$SELL_STATUS" "201"
  sale_ids+=("$(jq -r '.saleId' <<<"$SELL_BODY")")
done

step "Comprobando que los eventos quedan pendientes en el outbox"
wait_until "el outbox conserva los $SALES eventos como PENDING" outbox_count_with_status_is PENDING "$SALES" "${sale_ids[@]}"
check "el Catálogo no cambió" "$(catalog_stock "$SKU")" "$before"
check "el Catálogo sigue sano sin RabbitMQ" "$(http_status "$CATALOG_URL/actuator/health")" "200"

step "Reinicia RabbitMQ"
restart_ms="$(now_ms)"
start_service rabbitmq
check "RabbitMQ vuelve a estar sano" "$?" "0"
WAIT_TIMEOUT_SECONDS="$RECOVERY_TIMEOUT_SECONDS" wait_until "el outbox publica los $SALES eventos (PUBLISHED)" \
  outbox_count_with_status_is PUBLISHED "$SALES" "${sale_ids[@]}"
drain_ms=$(( $(now_ms) - restart_ms ))
WAIT_TIMEOUT_SECONDS="$RECOVERY_TIMEOUT_SECONDS" wait_until "el Catálogo converge a stock $((before - SALES))" \
  catalog_stock_is "$SKU" "$((before - SALES))"
catch_up_ms=$(( $(now_ms) - restart_ms ))

metric broker_recovery_catch_up_ms "$catch_up_ms"
