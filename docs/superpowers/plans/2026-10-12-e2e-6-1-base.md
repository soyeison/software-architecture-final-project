# E2E 6.1: librería, reinicio y escenarios REST — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crear la base de las pruebas de extremo a extremo —`e2e/lib.sh` con su autoprueba, `e2e/reset.sh` y el modo demo— y los cinco escenarios que solo usan REST: 01 venta POS, 02 venta online, 03 carrera por la última unidad, 04 venta sin stock y 10 seguridad.

**Architecture:** Scripts `bash` que corren contra el stack de desarrollo de Docker Compose con los puertos por defecto. Cada escenario es un script autónomo con su propio SKU de la semilla; las funciones comunes viven en `lib.sh` (sin lógica de escenarios). Los escenarios 01 y 02 comparten el flujo `sale-flow.sh`. Las esperas son por condición (`wait_until`), nunca pausas fijas.

**Tech Stack:** bash, curl, jq, Docker Compose, `rabbitmqctl` (vía `docker compose exec`), `scripts/generate-token.sh`.

**Spec:** `docs/superpowers/specs/2026-10-12-e2e-design.md` (secciones 1 a 5). Escenarios y comportamiento: `docs/superpowers/specs/2026-10-09-solucion-global-design.md` §4. Semilla: `docs/seed-data.md`.

## Global Constraints

- Nombres de archivos, funciones y variables en **inglés y completos**; mensajes de salida, comentarios y documentación en **español**. Commits en inglés, Conventional Commits, con la línea `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- `set -uo pipefail` **sin `-e`** (se ejecutan todas las comprobaciones y se agrega el resultado). Todos los `.sh` ejecutables (`chmod +x`; el repositorio normaliza a LF con `.gitattributes`).
- Se ejecutan contra el stack de desarrollo, proyecto Compose por defecto (`retail`) y puertos por defecto: Inventario `http://127.0.0.1:8081`, Catálogo `http://127.0.0.1:8082`. Variables opcionales: `INVENTORY_URL`, `CATALOG_URL`, `INVENTORY_SERVICE_PORT`, `CATALOG_SERVICE_PORT`, `WAIT_TIMEOUT_SECONDS` (30), `DEMO`.
- Cada escenario lee el estado actual de la API (no supone la semilla) y compara contra él; espera con `wait_until` (reintento cada 200 ms hasta `WAIT_TIMEOUT_SECONDS`).
- SKU por escenario: 01, 02 y 10 `TENIS-RUNNER-42`; 03 `BALON-FUTBOL-5` (stock exactamente 1, una vez por reinicio); 04 `CAMISETA-DRYFIT-M` (stock 0).
- Cola: `catalog.inventory-stock-changed`. Conteos de cola con `rabbitmqctl` (valor exacto), no con la consola de gestión.
- La ruta del repositorio contiene espacios: toda ruta en el código va entre comillas dobles.
- `reset.sh` es destructivo (`docker compose down -v`); ningún otro script lo invoca.

## Review Focus

1. **Esperas que no reintentan:** una condición pasada como `test "$(comando)" = x` se evalúa **una sola vez** antes de esperar. Las condiciones de `wait_until` deben ser funciones o comandos que se reevalúan (`catalog_stock_is`, `queue_is_empty`…). Lo fija `selftest.sh` (`wait_until`) y la revisión de cada escenario.
2. **Reejecución sin reset:** 01, 02, 04 y 10 deben poder repetirse; 03 debe fallar con el mensaje "Estado no inicial: ejecuta e2e/reset.sh" (no con un error críptico). Se comprueba en las Tareas 2 y 3.
3. **Stack apagado o argumento desconocido:** mensaje claro y código 1 (stack) o 2 (uso), nunca un volcado de `curl`/`jq`. Se comprueba en la Tarea 3.
4. **Comprobaciones que no pueden fallar:** cada escenario se rompe a propósito (mutación manual sin commitear) y debe terminar en `FALLÓ`. Se hace en las Tareas 2 y 3.
5. **La carrera del 03 es de verdad:** los dos tokens se generan antes y las dos ventas salen en segundo plano; el resultado válido es un `201` y un `409` por stock insuficiente y **un solo** evento nuevo.
6. **Ruta con espacios:** los scripts funcionan desde un directorio con espacios (se comprueba en la Tarea 3).

```bash
expect "statistics: sin valores devuelve 1" "$?" "1"

# --- is_integer ---
expect "is_integer acepta 386" "$(is_integer 386)" "yes"
expect "is_integer rechaza null" "$(is_integer null)" "no"
expect "is_integer rechaza vacío" "$(is_integer '')" "no"

# --- check ---
E2E_STATUS=0
check "descripción" "a" "a" >/dev/null
expect "check: igual no marca fallo" "$E2E_STATUS" "0"
check "descripción" "a" "b" >/dev/null
expect "check: distinto marca fallo" "$E2E_STATUS" "1"

# --- wait_until ---
E2E_STATUS=0
WAIT_TIMEOUT_SECONDS=2
wait_until "condición inmediata" true >/dev/null
expect "wait_until: éxito inmediato devuelve 0" "$?" "0"
expect "wait_until: éxito inmediato no marca fallo" "$E2E_STATUS" "0"

marker="$(mktemp -u)"
( sleep 0.6; touch "$marker" ) &
wait_until "condición que se cumple a los 0,6 s" test -e "$marker" >/dev/null
expect "wait_until: éxito tras esperar devuelve 0" "$?" "0"
expect "wait_until: registra al menos 500 ms esperados" "$([[ $WAITED_MS -ge 500 ]] && echo yes || echo no)" "yes"
rm -f "$marker"

wait_until "condición imposible" false >/dev/null
expect "wait_until: tiempo agotado devuelve 1" "$?" "1"
expect "wait_until: tiempo agotado marca fallo" "$E2E_STATUS" "1"
expect "wait_until: respeta el tiempo máximo (≥ 2000 ms)" "$([[ $WAITED_MS -ge 2000 ]] && echo yes || echo no)" "yes"

  exit 1
fi
```

`e2e/lib.sh`:

```bash
#!/usr/bin/env bash
# Funciones comunes de los escenarios E2E (spec E2E §2). Se carga con `source`; no ejecuta nada por sí sola
# y no contiene lógica de escenarios. Requiere bash, curl, jq y Docker Compose.

E2E_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
INVENTORY_URL="${INVENTORY_URL:-http://127.0.0.1:${INVENTORY_SERVICE_PORT:-8081}}"
CATALOG_URL="${CATALOG_URL:-http://127.0.0.1:${CATALOG_SERVICE_PORT:-8082}}"
WAIT_TIMEOUT_SECONDS="${WAIT_TIMEOUT_SECONDS:-30}"
QUEUE="catalog.inventory-stock-changed"
DEMO="${DEMO:-0}"

# Estado acumulado del escenario: 0 mientras todas las comprobaciones pasen.
E2E_STATUS=0
# Resultado de la última venta (ver `sell`) y del último `wait_until` (milisegundos esperados).
SELL_STATUS=""
SELL_BODY=""
WAITED_MS=0

# Ejecuta docker compose desde la raíz del repositorio (el stack de desarrollo, proyecto por defecto).
compose() { (cd "$E2E_ROOT" && docker compose "$@"); }

# Procesa los argumentos comunes de todos los escenarios: --demo (narración paso a paso).
e2e_init() {
  for argument in "$@"; do
    case "$argument" in
      --demo) DEMO=1 ;;
      *) echo "Uso: $0 [--demo]" >&2; exit 2 ;;
    esac
  done
}

# check <descripción> <valor obtenido> <valor esperado>
check() {
  if [[ "$2" == "$3" ]]; then
    echo "PASS: $1"
  else
    echo "FAIL: $1 (obtenido: $2, esperado: $3)"
    E2E_STATUS=1
  fi
}

# is_integer <valor>: imprime yes o no.
is_integer() { [[ "$1" =~ ^[0-9]+$ ]] && echo yes || echo no; }

# wait_until <descripción> <comando...>: reintenta cada 200 ms hasta WAIT_TIMEOUT_SECONDS. Deja los
# milisegundos esperados en WAITED_MS; imprime PASS o FAIL y devuelve 0 o 1.
wait_until() {
  local description="$1"
  shift
  local start_ns now_ns
  start_ns="$(date +%s%N)"
  while true; do
    if "$@" >/dev/null 2>&1; then
      now_ns="$(date +%s%N)"
      WAITED_MS=$(( (now_ns - start_ns) / 1000000 ))
      echo "PASS: $description (${WAITED_MS} ms)"
      return 0
    fi
    now_ns="$(date +%s%N)"
    WAITED_MS=$(( (now_ns - start_ns) / 1000000 ))
    if (( WAITED_MS >= WAIT_TIMEOUT_SECONDS * 1000 )); then
      echo "FAIL: $description (no ocurrió en ${WAIT_TIMEOUT_SECONDS} s)"
      E2E_STATUS=1
      return 1
    fi
    sleep 0.2
  done
}

# step <texto>: narra un paso. Con --demo muestra el texto destacado y espera Enter.
step() {
  if [[ "$DEMO" == "1" ]]; then
    printf '\n\033[1;36m▶ %s\033[0m\n' "$1"
    read -r -p "   (Enter para continuar) " _ || true
  else
    echo "-- $1"
  fi
}

# show <texto>: en modo demo muestra una petición o respuesta; si no, no imprime nada.
show() { [[ "$DEMO" == "1" ]] && printf '   %s\n' "$1"; return 0; }

# http_status <url>: código HTTP de un GET sin autenticación.
http_status() { curl -s --max-time 10 -o /dev/null -w '%{http_code}' "$1"; }

# token <pos|online|operator|no-scope>
token() { "$E2E_ROOT/scripts/generate-token.sh" "$1"; }

# sell <sku> <POS|ONLINE> [token] [cantidad]: registra una venta. Sin tercer argumento usa el token del
# canal; con "" no envía Authorization. Deja el código HTTP en SELL_STATUS y el cuerpo en SELL_BODY.
sell() {
  local sku="$1" channel="$2" quantity="${4:-1}" bearer
  if (( $# >= 3 )); then
    bearer="$3"
  elif [[ "$channel" == "POS" ]]; then
    bearer="$(token pos)"
  else
    bearer="$(token online)"
  fi
  local -a authorization=()
  [[ -n "$bearer" ]] && authorization=(-H "Authorization: Bearer $bearer")
  local body_file
  body_file="$(mktemp)"
  show "POST $INVENTORY_URL/api/v1/inventory/$sku/sales  {\"quantity\":$quantity,\"channel\":\"$channel\"}"
  SELL_STATUS="$(curl -s --max-time 10 -o "$body_file" -w '%{http_code}' -X POST \
    "$INVENTORY_URL/api/v1/inventory/$sku/sales" "${authorization[@]}" \
    -H 'Content-Type: application/json' -d "{\"quantity\":$quantity,\"channel\":\"$channel\"}")"
  SELL_BODY="$(cat "$body_file")"
  rm -f "$body_file"
  show "← $SELL_STATUS $SELL_BODY"
}

# catalog_product <sku>: JSON de la consulta del Catálogo.
catalog_product() { curl -s --max-time 10 "$CATALOG_URL/api/v1/catalog/products/$1"; }
# catalog_field <sku> <filtro jq>: un campo de la consulta del Catálogo.
catalog_field() { catalog_product "$1" | jq -r "$2"; }
catalog_stock() { catalog_field "$1" '.availableStock'; }
# catalog_stock_is <sku> <stock>: éxito si el Catálogo muestra ese stock (para wait_until).
catalog_stock_is() { [[ "$(catalog_stock "$1")" == "$2" ]]; }

# inventory_stock <sku>: stock actual según Inventario (token de operador).
inventory_stock() {
  curl -s --max-time 10 -H "Authorization: Bearer $(token operator)" "$INVENTORY_URL/api/v1/inventory/$1" | jq -r '.stock'
}

# outbox_count <sku>: eventos del SKU entre los 50 más recientes del outbox.
outbox_count() {
  curl -s --max-time 10 "$INVENTORY_URL/api/v1/inventory/outbox" | jq --arg sku "$1" '[.[] | select(.sku == $sku)] | length'
}
# outbox_count_is <sku> <cantidad> (para wait_until)
outbox_count_is() { [[ "$(outbox_count "$1")" == "$2" ]]; }
# outbox_event_published <eventId>: éxito si el evento figura PUBLISHED.
outbox_event_published() {
  curl -s --max-time 10 "$INVENTORY_URL/api/v1/inventory/outbox" \
    | jq -e --arg id "$1" 'any(.[]; .eventId == $id and .status == "PUBLISHED")' >/dev/null
}

# queue_messages <cola>: mensajes de una cola con rabbitmqctl (valor exacto, sin el retraso de la consola).
queue_messages() {
  compose exec -T rabbitmq rabbitmqctl -q list_queues name messages | awk -v q="$1" '$1 == q {print $2}' | tr -d '\r'
}

# queue_is_empty <cola>: éxito si la cola no tiene mensajes (para wait_until).
queue_is_empty() { [[ "$(queue_messages "$1")" == "0" ]]; }

# synced <sku>: éxito si el Catálogo muestra el mismo stock que Inventario.
synced() { [[ "$(catalog_stock "$1")" == "$(inventory_stock "$1")" ]]; }

# fail_precondition <mensaje>: termina el escenario sin ejecutarlo.
fail_precondition() {
  echo "FAIL: $1"
  echo "      Estado no inicial: ejecuta e2e/reset.sh y vuelve a intentarlo."
  exit 1
}

# require_stack: herramientas instaladas y ambos servicios respondiendo.
require_stack() {
  local tool
  for tool in docker curl jq; do
    command -v "$tool" >/dev/null || { echo "FAIL: se requiere $tool en el equipo"; exit 1; }
  done
  local url
  for url in "$INVENTORY_URL" "$CATALOG_URL"; do
    if ! curl -s -f --max-time 5 -o /dev/null "$url/actuator/health"; then
      echo "FAIL: $url no responde. Levanta el stack con: docker compose up -d --wait"
      exit 1
    fi
  done
}

# require_synced <sku>: espera a que el Catálogo coincida con Inventario antes de empezar.
require_synced() {
  wait_until "el Catálogo está sincronizado con Inventario para $1" synced "$1" \
    || fail_precondition "el Catálogo no coincide con Inventario para $1"
}

# require_stock <sku> <mínimo>: stock suficiente para el escenario.
require_stock() {
  local stock
  stock="$(inventory_stock "$1")"
  [[ "$stock" =~ ^[0-9]+$ ]] && (( stock >= $2 )) \
    || fail_precondition "$1 tiene stock $stock y el escenario necesita al menos $2"
}

# statistics <valores...>: deja STAT_MIN, STAT_AVERAGE (un decimal), STAT_P95 (rango más cercano) y STAT_MAX.
# Devuelve 1 si no recibe valores.
statistics() {
  (( $# > 0 )) || return 1
  local summary
  summary="$(printf '%s\n' "$@" | sort -n | awk '
    { values[NR] = $1; sum += $1 }
    END {
      rank = int(0.95 * NR); if (rank < 0.95 * NR) rank++
      printf "%s %.1f %s %s", values[1], sum / NR, values[rank], values[NR]
    }')"
  read -r STAT_MIN STAT_AVERAGE STAT_P95 STAT_MAX <<<"$summary"
}

# finish <nombre del escenario>: imprime el resultado y termina con el código acumulado.
finish() {
  if [[ $E2E_STATUS -eq 0 ]]; then echo "Escenario OK: $1"; else echo "Escenario FALLÓ: $1"; fi
  exit "$E2E_STATUS"
}
```

```bash
# Devuelve el stack de desarrollo a un estado inicial conocido (spec E2E §4): borra contenedores y volúmenes
```

```bash
#!/usr/bin/env bash
# Flujo común de los escenarios 1 y 2 (spec global §4.1): una venta se refleja en el Catálogo. Se carga con
# `source` desde 01-pos-sale.sh y 02-online-sale.sh.

source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"

# run_sale_scenario <nombre del escenario> <POS|ONLINE> [--demo]
run_sale_scenario() {
  local name="$1" channel="$2"
  shift 2
  e2e_init "$@"
  local sku="TENIS-RUNNER-42"

  require_stack
  require_synced "$sku"
  require_stock "$sku" 1
  local before expected sale_id latency
  before="$(catalog_stock "$sku")"
  expected=$((before - 1))

  step "Venta de 1 unidad de $sku por el canal $channel (stock actual: $before)"
  sell "$sku" "$channel"
  check "la venta $channel responde 201" "$SELL_STATUS" "201"
  check "Inventario informa el stock restante $expected" "$(jq -r '.remainingStock' <<<"$SELL_BODY")" "$expected"
  sale_id="$(jq -r '.saleId' <<<"$SELL_BODY")"

  step "Esperando que el Catálogo refleje la venta"
  wait_until "el Catálogo muestra stock $expected" catalog_stock_is "$sku" "$expected"
  latency="$(catalog_field "$sku" '.lastEventLatencyMs')"
  check "lastEventLatencyMs se informa" "$(is_integer "$latency")" "yes"
  echo "INFO: latencia venta -> Catálogo: ${latency} ms"

  step "Comprobando el outbox de Inventario y la cola del Catálogo"
  wait_until "el evento de la venta figura PUBLISHED en el outbox" outbox_event_published "$sale_id"
  wait_until "la cola $QUEUE queda vacía" queue_is_empty "$QUEUE"

  finish "$name"
}
```

`e2e/03-last-unit-race.sh`:

```bash
#!/usr/bin/env bash
# Escenario 3 — Carrera por la última unidad (spec global §4.2): con stock 1, POS y online venden a la vez;
# una obtiene 201, la otra 409, y se genera un solo evento. Requiere BALON-FUTBOL-5 con stock exactamente 1,
# así que solo corre una vez por reinicio (e2e/reset.sh). Uso: e2e/03-last-unit-race.sh [--demo]
set -uo pipefail
source "$(dirname "${BASH_SOURCE[0]}")/lib.sh"
e2e_init "$@"
SKU="BALON-FUTBOL-5"

require_stack
require_synced "$SKU"
stock="$(inventory_stock "$SKU")"
[[ "$stock" == "1" ]] || fail_precondition "$SKU tiene stock $stock y el escenario necesita exactamente 1"
events_before="$(outbox_count "$SKU")"

results="$(mktemp -d)"
trap 'rm -rf "$results"' EXIT
pos_token="$(token pos)"
online_token="$(token online)"

step "POS y online venden la última unidad de $SKU al mismo tiempo"
( sell "$SKU" POS "$pos_token";       echo "$SELL_STATUS" >"$results/pos.status";    echo "$SELL_BODY" >"$results/pos.body" ) &
( sell "$SKU" ONLINE "$online_token"; echo "$SELL_STATUS" >"$results/online.status"; echo "$SELL_BODY" >"$results/online.body" ) &
wait

statuses="$(cat "$results/pos.status" "$results/online.status" | sort -n | paste -sd' ')"
check "una venta responde 201 y la otra 409" "$statuses" "201 409"
loser_body="$results/online.body"
[[ "$(cat "$results/pos.status")" == "409" ]] && loser_body="$results/pos.body"
check "el rechazo es por stock insuficiente" "$(jq -r '.type | endswith("insufficient-stock")' "$loser_body")" "true"
check "el stock en Inventario es 0" "$(inventory_stock "$SKU")" "0"

step "Comprobando que se generó un solo evento y que el Catálogo converge"
wait_until "el outbox tiene exactamente un evento nuevo de $SKU" outbox_count_is "$SKU" "$((events_before + 1))"
wait_until "el Catálogo muestra stock 0" catalog_stock_is "$SKU" 0
check "el Catálogo marca el producto sin disponibilidad" "$(catalog_field "$SKU" '.inStock')" "false"

finish "03 Carrera por la última unidad"
```
